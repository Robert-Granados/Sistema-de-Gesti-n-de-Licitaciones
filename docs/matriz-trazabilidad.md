# Matriz de trazabilidad

Esta matriz relaciona cada historia de usuario con criterios, Issue, pruebas,
commits, Pull Request, documentación y pequeña liberación. Su finalidad es que
la evidencia pueda verificarse sin inferir relaciones entre artefactos.

## Criterio y alcance

- Los criterios completos están en la tarjeta de
  [historias de usuario](historias-usuario.md) y en el Issue enlazado.
- **Directa** significa que el mensaje del commit identifica la historia.
- **Agrupada** significa que un commit o PR implementó varias historias. Se
  conserva la referencia histórica real y no se reescriben commits.
- Las pruebas indicadas son representativas; el pipeline ejecuta las suites
  completas y constituye la evidencia reproducible de resultado.
- Los Issues #31 a #84 fueron creados retrospectivamente en la auditoría final.
  Sus fechas no se presentan como evidencia de planificación original.

Repositorio: `Robert-Granados/Sistema-de-Gesti-n-de-Licitaciones`.

## Limitaciones declaradas

- La asociación de las historias tempranas con commits agrupados es indirecta.
- Los Issues históricos no demuestran que GitHub Issues se usara durante el
  desarrollo; permiten navegar la evidencia existente durante la evaluación.
- La matriz demuestra cobertura verificable, pero no convierte pruebas escritas
  después de la implementación en evidencia de TDD.
- La validación de Kubernetes es estructural; el despliegue en un clúster real
  continúa declarado como pendiente.
